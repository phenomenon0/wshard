# demo_identity — dogfood demo for W-SHARD `meta/identity`

Simulates a fabric-style agent-memory worker's write path and proves the
Phase-3 identity success criteria in-process on this machine. New files only,
lives entirely in this directory; nothing else in the repo is touched.

## What it proves

1. **Compression-agnostic identity** — one logical episode, three encodings
   (`none`, `zstd`, `lz4` → 7136 / 2400 / 3392 bytes on disk) has one
   byte-identical `episode_identity`.
2. **Tamper detection** — one flipped byte inside `signal/state` with its
   CRC32C patched: the container loads fine (CRC cannot tell), but
   `verify_identity()` fails in both Go and Python, naming `signal/state`.
   Trusted `episode_identity()` is unchanged (it trusts the committed block).
3. **Cross-language** — Python derives the same 64-hex identity from the
   Go-written file that Go computed, and Go's `VerifyIdentity` accepts the
   Python-written zstd file and agrees on its identity.

The payload per episode: a real `float32` LE tensor block (`signal/state`,
T=128 × 8, exact `m/8` values so Go/Python agree bit-for-bit), state/metadata
JSON (`meta/episode` `metadata` map, Go writer), and UTF-8 text notes
(`signal/notes`, one byte per timestep).

## Run

```sh
cd demo_identity
go run .          # Go orchestrator + assertions; shells out to python3 for the companion verifier
```

Requires: a Go toolchain (module `wshard.demo_identity` replaces
`github.com/phenomenon0/wshard/go => ../go`), and `python3` with the wshard py
deps (`numpy`, `crc32c`, …) plus the `glyph-py` canon (`canon_json`) importable
— no install needed beyond what the py test suite already uses. The verifier
adds `../py` to `sys.path` itself.

## Notes / findings surfaced by the demo

- **Hash canon**: the identity value is sha256 over *canonical JSON* of
  `{"v":1,"leaf":"sha256","entries":{name:sha256(uncompressed-bytes)}}` — never
  raw bytes. Go writes the canon by hand in `go/shard/canonjson.go` — sorted
  keys, RFC 8785 §3.2.2.2 escaping — rather than through `encoding/json`, which
  escapes `<`, `>` and `&` and would diverge on any block name containing them;
  Python uses glyph-py `canon_json(from_json_loose(…))`. They are byte-identical
  in both directions (Go verifies Python-written files and vice-versa).
- **Identity is per-container-content, not per-episode-logic across writers**:
  Go's `CreateWShard` and Python's `save_wshard` of the "same" episode produce
  different identity values, because Python emits a `time/ticks` block and
  richer `meta/*` JSON that Go does not (7 vs 8 leaves). Within one writer,
  encoding never changes the identity. A mixed Go/Py fabric fleet should treat
  identity as addressing the file's entry set, and keep one writer layout per
  episode lineage.
- Go's typed `CreateWShard` never compresses entries; compressed+identity
  coverage in Go comes from the golden `per_block_compressed.wshard`
  (generated by the standalone `golden/generate.go` writer) verified by
  `TestGoldenIdentityVerifies`, plus this demo's Go-verifies-Python-zstd check.
